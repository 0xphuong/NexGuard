# Migration runbook — v3.0.0 (L7-D — proxy daemon GA)

> **Scope**: ships the L7 transparent proxy daemon (`proxy/` in this
> repo) + the mTLS-protected internal control plane Caddy listener
> at `:13443` + a per-host hard-block of `/internal/*` on the
> public :443 listener. No new SQL migrations. **L7 enforcement
> remains opt-in via the org-level `l7_enabled` toggle** — flipping
> it on with this version actually steers VPN traffic through the
> proxy (in v2.4.0 the chain was installed but the destination at
> `127.0.0.1:8443` had nothing listening; in v3.0.0 the proxy
> daemon picks up those connections).

## Summary

| Piece | Lives in | Active when |
|---|---|---|
| Hard 404 on `/internal/*` at public :443 | `docker-compose.prod.yml` (Caddy block) | always after upgrade |
| mTLS Caddy listener at :13443 | `docker-compose.prod.yml` + cert files | when certs are provisioned (see Pre-flight) |
| L7 proxy daemon container | `docker-compose.proxy.yml` overlay | when the operator activates the overlay |

## Pre-flight

### 1. Provision the mTLS certs

```bash
sudo ./scripts/l7-rotate-proxy-cert.sh
```

Outputs land in `/var/nexguard/l7-certs/` by default (override via
`NEXGUARD_CERTS_DIR`). Three pieces of material:

| File | Used by |
|---|---|
| `internal-ca.pem` | Caddy (trust anchor for client certs) + proxy (trust anchor for server cert) |
| `internal-server.{pem,key}` | Caddy presents on :13443 |
| `proxy.{pem,key}` | Proxy daemon presents as client to :13443 |

The Caddy container expects to find these at
`/etc/nexguard/l7-certs/`; the prod compose mounts
`${FZ_INSTALL_DIR:-.}/l7-certs/` so make sure to either set
`NEXGUARD_CERTS_DIR=${FZ_INSTALL_DIR:-.}/l7-certs` when running the
rotation script, or symlink the output directory.

### 2. Take a database backup (still good practice even on a
no-migration upgrade):

```bash
docker compose -f docker-compose.prod.yml exec db \
  pg_dump -U postgres -d nexguard_dev \
  > ~/nexguard-pre-v3.0.0-$(date +%Y%m%dT%H%M%SZ).sql
```

### 3. Confirm Linux kernel + nftables prerequisites still met

Same as v2.4.0 — kernel ≥ 5.6.9 for the TPROXY chain. No change
in v3.0.0.

## Apply (Caddy mTLS only — proxy daemon NOT yet running)

```bash
cd /path/to/nexguard-prod
git pull origin main
docker compose -f docker-compose.prod.yml up -d --build
```

Verify the public :443 now hard-404s `/internal/*`:

```bash
curl -sI https://<your-portal>/internal/bundle.json | head -3
# Expect: HTTP/2 404
```

Verify the mTLS listener accepts your proxy cert:

```bash
curl --cacert /var/nexguard/l7-certs/internal-ca.pem \
     --cert   /var/nexguard/l7-certs/proxy.pem \
     --key    /var/nexguard/l7-certs/proxy.key \
     https://127.0.0.1:13443/internal/bundle.json | jq '.bundle_version'
# Expect: an integer (the current bundle version)
```

Verify the mTLS listener rejects requests without a client cert:

```bash
curl -k https://127.0.0.1:13443/internal/bundle.json
# Expect: TLS handshake error (no client certificate)
```

## Apply (proxy daemon active — full L7-D)

```bash
docker compose -f docker-compose.prod.yml \
               -f docker-compose.coredns.yml \
               -f docker-compose.proxy.yml up -d --build
```

The proxy container mounts the cert files from
`${FZ_INSTALL_DIR:-.}/l7-certs/` read-only and uses them as the
client cert to reach Caddy at `https://127.0.0.1:13443`. Its
defaults assume the certs landed in the standard path; override
`NEXGUARD_SERVER_URL` in `.env` for non-standard deployments.

Wait ~10 s for the boot probe, then verify:

```bash
docker compose -f docker-compose.proxy.yml exec proxy /usr/local/bin/nexguard-proxy --health-probe
# Exit code 0 (ready). curl http://127.0.0.1:9090/metrics from the host for the full picture.
```

## Operating the kill switch

Only after every piece of L7 plumbing is in place AND a smoke-test
app has been declared in the admin UI:

1. Flip the org toggle at `/settings/l7` → ON.
2. fz_wall installs the TPROXY chain (PubSub-driven, within ms).
3. New TCP connections to declared VIPs flow:

```
VPN client → wg-nexguard → nftables tproxy chain → 127.0.0.1:8443 (proxy)
            ↓
proxy looks up identity via mTLS GET /internal/sessions/by_vpn_ip/:ip
       ↓
proxy evaluates policy from the cached signed bundle
       ↓
proxy → backend app, with X-NexGuard-Identity-Jwt header
```

If anything goes wrong, **flip the toggle off**. The TPROXY chain
is removed within ms and traffic falls back to plain L3 routing.

## Cert lifecycle

* **Proxy cert** expires 365 days after issuance. Re-run the
  rotation script before then:

  ```bash
  sudo ./scripts/l7-rotate-proxy-cert.sh
  docker compose -f docker-compose.prod.yml restart caddy
  docker compose -f docker-compose.proxy.yml restart proxy
  ```

* **Internal CA** expires 10 years after issuance. Use
  `--reset-ca` to rotate it; this invalidates every previously
  issued proxy cert, so plan a maintenance window.

* Archived certs land under `<NEXGUARD_CERTS_DIR>/archive/<ts>/`
  in case a recently-issued JWT is still in flight against an
  old key.

## Rollback

Three independent rollback paths, choose the smallest hammer:

1. **Flip `l7_enabled` off.** Restores L3 routing instantly. The
   proxy container keeps running but receives no traffic.
2. **Take the proxy overlay down.** `docker compose -f
   docker-compose.proxy.yml down`. The :13443 Caddy listener keeps
   running but has no client.
3. **Downgrade the whole stack to v2.4.0.** Rebuild from the tag
   and redeploy; the proxy is not in v2.4.0 so the absence is
   automatic.

## Operational notes

- **`/internal/*` is no longer reachable from the public DNS.**
  External clients (browsers, the user's NexGuard Connect app)
  never had a reason to hit those paths; the hard-404 stops any
  leakage even with a misconfigured Caddy.
- **Identity cache invalidation.** On every bundle pivot the proxy
  clears its 30 s identity cache. Group / scope / role changes
  picked up by the bundle compile (≤ 300 ms debounce on the server
  side) propagate to the proxy as soon as the next poll fires
  (currently 30 s; a follow-up release switches to PubSub-driven
  pivot for sub-second invalidation).
- **JWT signing key minimum is 2048 bits.** The proxy refuses to
  load a bundle whose `signing_key.private_pem` is weaker. Match
  what `FzHttp.L7.JwtSigner` generates by default.
- **Backend scheme allow-list.** App `backend` URLs are restricted
  to `http://` and `https://`. Anything else (file, gopher, …)
  fails the bundle pivot at the proxy with a clear error.
- **Outbound TLS pinned at TLS 1.2+** on the backend hop. Match
  the ADR-007 commitment.
