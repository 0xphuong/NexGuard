# Migration runbook — v3.0.1 (L7-D hardening + DNS ops)

> **Scope**: post-v3.0.0 hardening from the security backlog +
> CoreDNS routing fixes hit during prod smoke. No SQL migrations,
> no new compose services. **One BREAKING change for backends**:
> JWT payload gained `iss`, `aud`, `jti`, `nbf` claims and apps
> sitting behind the proxy MUST start validating `iss` and `aud`
> (see [Backend integration](#backend-integration-jwt-claims)) —
> the proxy is now actively pinning tokens to the issuing app to
> close a cross-app replay window.

## Summary

| Area | Change | Operator action | Backend action |
|---|---|---|---|
| **JWT** | Adds `iss` / `aud` / `jti` / `nbf` claims | none | **REQUIRED** — assert `iss == "nexguard-proxy"` and `aud == <your app uuid>` |
| **Proxy** | Strips client-sent `X-Forwarded-*`, normalises path, redacts JWT signature in logs, zeros PEM after parse, guards `WriteHeader` | none | If your app trusted `X-Forwarded-For` from arbitrary client headers, switch to the proxy-issued canonical header |
| **Audit log** | Whitelist gains 12 L7 / app / group / scope actions | none | none |
| **CoreDNS** | `fallthrough .` (sister names under your zone now resolve); optional `COREDNS_FORWARD_TO_FALLBACK` for HA bind9 pair | optional: set `COREDNS_FORWARD_TO_FALLBACK` in `.env` | none |
| **WG config render** | L7 VIP /16 auto-appended to client `AllowedIPs` | existing clients re-download `.conf` | none |
| **Deny page** | Redesigned (security-grade, dark mode, per-status messaging) | none | none |

## Pre-flight

### 1. Roll out backend JWT validation FIRST

If you ship the proxy update before backends know about `iss`/`aud`,
nothing breaks — backends that ignore unknown claims still accept
the token. But if you ship backend `aud` enforcement against a
proxy that doesn't stamp it (pre-v3.0.1), backends reject every
request → outage. Order matters:

1. Backend team adds `iss` + `aud` checks (forward-compatible — old
   proxies didn't send them, so allow missing claims during the
   bake window).
2. Deploy proxy v3.0.1 — now stamps the claims.
3. Backend team flips checks from "lenient" to "strict" (reject if
   claims missing or wrong).

For new deployments without that legacy: just enforce strict from
the start.

### 2. Database backup (cheap insurance)

```bash
docker compose -f docker-compose.prod.yml exec db \
  pg_dump -U postgres -d nexguard_dev \
  > ~/nexguard-pre-v3.0.1-$(date +%Y%m%dT%H%M%SZ).sql
```

## Backend integration: JWT claims

The proxy mints a fresh JWT per upstream request and forwards it
in a custom header:

```
X-NexGuard-Identity-Jwt: <header>.<payload>.<signature>
```

(NOT `Authorization: Bearer` — the proxy keeps `Authorization`
untouched so backends can use it for their own purposes.)

Up to v3.0.0 the payload looked like:

```json
{ "user_id": "...", "email": "...", "groups": [...],
  "mfa_age_seconds": 142,
  "iat": 1719312000, "exp": 1719312300 }
```

From v3.0.1 onward it also stamps:

```json
{ "iss": "nexguard-proxy",
  "aud": "<the L7 app's UUID — Ecto :binary_id>",
  "jti": "<16-hex random per call>",
  "nbf": <same as iat> }
```

### Why aud matters

Without `aud`, a token minted for app A is structurally identical
to a token minted for app B — same user, same groups, same
signature key. If an attacker proxies a captured token from a
compromised app A backend toward app B, app B can't tell. With
`aud`, app B asserts `aud == <my uuid>` and rejects the replayed
token. Same for `iss`: if a non-NexGuard JWT somehow lands at a
backend, the missing/wrong `iss` rejects it.

### Backend validation contract

Every L7-protected backend MUST validate:

| Claim | Check | On failure |
|---|---|---|
| `iss` | `== "nexguard-proxy"` | 403 |
| `aud` | `== <this backend's app UUID>` (the one shown on `/applications/<id>`) | 403 |
| `exp` | `> now()` | 401 |
| `nbf` | `<= now()` (with ±60s clock skew tolerance) | 401 |

The app UUID is the value of the `id` column for that application
row in NexGuard — visible in the admin UI URL when you edit the
app: `/applications/<uuid>/edit`.

### Go example

```go
type Claims struct {
    Iss    string   `json:"iss"`
    Aud    string   `json:"aud"`
    UserID string   `json:"user_id"`
    Email  string   `json:"email"`
    Groups []string `json:"groups"`
    Exp    int64    `json:"exp"`
    Nbf    int64    `json:"nbf"`
}

func nexguardMW(myAppID string, next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        jws := r.Header.Get("X-NexGuard-Identity-Jwt")
        if jws == "" {
            http.Error(w, "missing identity header", 403)
            return
        }
        claims, err := verifyAndParse(jws) // signature check via JWKS
        if err != nil {
            http.Error(w, "bad token", 403)
            return
        }
        if claims.Iss != "nexguard-proxy" {
            http.Error(w, "invalid issuer", 403); return
        }
        if claims.Aud != myAppID {
            http.Error(w, "token not for this app", 403); return
        }
        now := time.Now().Unix()
        if claims.Exp < now || claims.Nbf > now+60 {
            http.Error(w, "expired or not yet valid", 401); return
        }
        next.ServeHTTP(w, r)
    })
}
```

### Elixir / Phoenix example

```elixir
defmodule MyApp.NexGuardPlug do
  import Plug.Conn

  @issuer "nexguard-proxy"
  @app_id Application.compile_env!(:my_app, :nexguard_app_id)

  def call(conn, _opts) do
    with [jws]         <- get_req_header(conn, "x-nexguard-identity-jwt"),
         {:ok, claims} <- verify_signature(jws),  # against /.well-known/jwks.json
         :ok           <- check_iss(claims),
         :ok           <- check_aud(claims),
         :ok           <- check_time(claims) do
      assign(conn, :nexguard_user, claims)
    else
      _ -> conn |> send_resp(403, "forbidden") |> halt()
    end
  end

  defp check_iss(%{"iss" => @issuer}), do: :ok
  defp check_iss(_),                   do: {:error, :bad_issuer}

  defp check_aud(%{"aud" => @app_id}), do: :ok
  defp check_aud(_),                   do: {:error, :bad_audience}

  defp check_time(%{"exp" => exp, "nbf" => nbf}) do
    now = System.system_time(:second)
    cond do
      exp < now      -> {:error, :expired}
      nbf > now + 60 -> {:error, :not_yet_valid}
      true           -> :ok
    end
  end
end
```

The public JWKS for verifying the signature is at the standard
IETF path on the public listener — no mTLS, no auth, plain HTTPS:

```
GET https://<your-nexguard-portal>/.well-known/jwks.json
```

Returns `{"keys": [<active>, <grace1>, ...]}` — each entry is a
JWK with `kid`, `kty`, `use: "sig"`, `alg: "RS256"`, and the RSA
modulus/exponent. Match the JWT header's `kid` to the right key.
The grace key(s) cover the rotation window so tokens signed just
before a rotation still verify briefly after.

(The mTLS endpoint `:13443/internal/bundle.json` is for the proxy
daemon only — it serves the full policy bundle, not just keys.)

## Hardening details (FYI)

These are silent improvements — no operator or backend action
needed, listed here so you know what landed.

| Change | What it kills |
|---|---|
| **X-Forwarded-\* stripped** before forward | Client-supplied IP spoofing in app logs / WAF rules. Proxy then re-adds a canonical `X-Forwarded-For` with the real WG-side client IP. |
| **Path normalisation** | `..`, double-slash, percent-encoded traversal rejected in policy eval — no more sneaking past path-prefix rules. |
| **Log redaction** | JWT signature segment never appears in proxy logs — only header + payload metadata. |
| **PEM zeroed in memory** | Signing key raw bytes wiped after parse — proxy no longer holds the PEM string for GC. |
| **WriteHeader guard** | Defensive `sync.Once`-like guard around response writes; prevents a panic if a buggy code path writes twice. |
| **JWT `nbf`** | One-minute clock skew tolerance is the convention; tokens not yet valid get a clean 401 instead of an obscure crypto error. |

## CoreDNS

### `fallthrough .` fix (auto-applied)

Sister names under your declared internal zone (e.g.
`grafana.<zone>` when only `hq.<zone>` is L7-onboarded) used to
return NXDOMAIN — the hosts plugin was claiming authority over the
whole zone. Now they fall through to the forward plugin and
resolve normally. Bind-mounted Corefile; auto-deployed on upgrade.

### Optional HA pair (new env knob)

```bash
# .env
COREDNS_FORWARD_TO=10.0.235.250          # primary
COREDNS_FORWARD_TO_FALLBACK=10.0.235.251 # only if you have a redundant DNS
```

`policy sequential` keeps every query on the primary while it's
healthy, so the cache stays hot on one box. Fail-over happens only
when the primary fails its health check (every 5s), not on every
query. Leaving `_FALLBACK` unset is safe — it defaults to the
primary, equivalent to "no failover".

### Recommended bind9-side tuning

If you point `COREDNS_FORWARD_TO` at corporate bind9, the gateway
will look like one heavy /32 source to it. Two minimum tweaks
worth coordinating with the DNS team:

1. **`exempt-clients`** — add the gateway's IP to the RRL exempt
   list. CoreDNS already self-shapes with `max_concurrent 100` +
   `serve_stale` + `prefetch`; RRL on the bind9 side just causes
   retries and amplifies load.
2. **Raise client caps** — `recursive-clients 4000`,
   `tcp-clients 500`, `max-cache-size 512m`, enable
   `prefetch 2 9;` and `stale-answer-enable yes;`.

## Rollback

Local rollback is safe AS LONG AS backends haven't moved to
strict-mode JWT validation. If they have:

| Component to rollback | Safe? |
|---|---|
| Proxy v3.0.1 → v3.0.0 | Only if backends are still in lenient mode (accept missing iss/aud). Otherwise backends will 403 every request. |
| CoreDNS Corefile changes | Safe — bind-mounted, revert + `docker compose restart coredns`. |
| Audit log whitelist | Safe — drops back to "Logger.error spam" but no functional break. |

Rollback command:

```bash
git revert <commit-sha>...<commit-sha>
docker compose -f docker-compose.prod.yml \
               -f docker-compose.coredns.yml \
               -f docker-compose.proxy.yml \
               up -d --build
```

## Smoke tests

After upgrade, verify:

```bash
# 1. L7 still works end-to-end
curl -sI -k https://hq.<your-zone>/                  # 302 (auth) or 200

# 2. JWKS endpoint is serving the active key
curl -sk https://<your-portal>/.well-known/jwks.json | jq '.keys[0] | {kid, alg, use}'
# expected: { "kid": "<uuid>", "alg": "RS256", "use": "sig" }

# 3. CoreDNS resolves sister names
docker compose -f docker-compose.prod.yml exec -T nexguard \
   nslookup grafana.<your-zone> 127.0.0.1
# returns real IP, not NXDOMAIN

# 4. Audit log no longer spams Logger.error
docker compose -f docker-compose.prod.yml logs --since 5m phoenix 2>&1 \
   | grep -c "AuditLogs.log failed"
# expect 0 from normal admin clicks
```
