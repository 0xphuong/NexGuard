# Migration runbook — v2.4.0 (L7-C network plumbing)

> **Scope**: nftables TPROXY chain + ip rule + CoreDNS sidecar +
> hosts-file generator. No new SQL migrations. The whole stack
> ships **dormant**: the TPROXY chain only installs when
> `org_settings.l7_enabled = true`, and even with the chain
> installed, packets to declared VIPs land in a closed port at
> 127.0.0.1:8443 until the L7 proxy daemon (L7-D) is deployed.
> **Keep `l7_enabled = false` until L7-D ships.**

## Summary

| Piece | Lives in | Active when |
|---|---|---|
| `FzWall.CLI.Helpers.Tproxy` | nftables shell-out | `l7_enabled = true` (chain) + always (fwmark route) |
| `FzHttp.L7.CoreDnsHosts` | Phoenix GenServer | always; file is empty until an Application is enabled |
| `docker-compose.coredns.yml` | Opt-in compose overlay | operator runs `-f` with both compose files |

## Pre-flight

### 1. Kernel version

The `tproxy` statement landed in nftables proper at kernel 5.6 and is
stable from 5.6.9 onward. Confirm:

```bash
uname -r
# expected: 5.6.9 or newer (most current LTS kernels work)
```

If you're on Ubuntu 22.04 LTS or newer, you're already past 5.15 and
have nothing to do here.

### 2. IPv6 status

L7-C TPROXY is **IPv4-only** in v2.4.0. The L7 proxy daemon (L7-D)
will handle dual stack; until then, declared apps respond only on
their IPv4 VIPs. If you've enabled WG IPv6, that's fine — IPv6 VPN
traffic to non-VIP destinations passes through unchanged.

### 3. Port 53 availability (CoreDNS only)

If you plan to enable the CoreDNS overlay, port 53 on the host must
be free. On default Ubuntu / Debian, systemd-resolved owns :53:

```bash
sudo ss -tunlp | grep ':53 '
# look for systemd-resolved
```

To free it:

```bash
sudo systemctl stop systemd-resolved
sudo systemctl disable systemd-resolved

# Replace /etc/resolv.conf so the host itself still resolves:
sudo rm /etc/resolv.conf
echo 'nameserver 1.1.1.1' | sudo tee /etc/resolv.conf
```

(Or rebind systemd-resolved to a non-:53 port via
`/etc/systemd/resolved.conf` if you prefer.)

If you do NOT enable the CoreDNS overlay, you can skip this entirely.

## Apply (without CoreDNS — default)

Standard upgrade:

```bash
cd /path/to/nexguard-prod
git pull origin main
docker compose -f docker-compose.prod.yml up -d --build
```

On boot you should see:

```
[fz_wall] starting up
[L7] added fwmark route to table 100
[L7] added fwmark 0x1 → table 100 rule
```

(If `l7_enabled = false`, which is the default, the TPROXY chain
itself is NOT installed — only the routing primitives.)

CoreDnsHosts GenServer also boots and writes the file:

```bash
docker compose -f docker-compose.prod.yml exec nexguard \
  cat /etc/nexguard/internal-hosts 2>/dev/null || echo "file path not mounted"
```

By default the file path is inside the container only — the host
doesn't see it. To expose it (needed for the CoreDNS overlay), add
a bind mount; see the CoreDNS overlay section.

## Apply (with CoreDNS overlay — opt-in)

Stop the running stack, then bring it up with both compose files:

```bash
cd /path/to/nexguard-prod
git pull origin main
docker compose -f docker-compose.prod.yml down
docker compose -f docker-compose.prod.yml \
               -f docker-compose.coredns.yml up -d --build
```

Verify the sidecar is up:

```bash
docker compose -f docker-compose.prod.yml -f docker-compose.coredns.yml ps coredns
```

And that the shared hosts file is being written:

```bash
cat coredns-hosts/internal-hosts
# expected (when no apps enabled):
# # generated by FzHttp.L7.CoreDnsHosts — do not edit by hand
```

After creating + enabling an application in the admin UI:

```bash
cat coredns-hosts/internal-hosts
# # generated by FzHttp.L7.CoreDnsHosts — do not edit by hand
# 10.99.0.5 wiki.internal
```

CoreDNS picks it up within 1 second (`reload 1s` directive).

## Verify TPROXY plumbing

This is the risky bit. Do **not** flip `l7_enabled` to `true` until
L7-D is also deployed; the steps below assume `l7_enabled = false`
(safe) — they just inspect the always-installed routing primitives.

```bash
# fwmark route (installed on every fz_wall boot)
docker compose -f docker-compose.prod.yml exec nexguard ip route show table 100
# expected: local default dev lo scope host

docker compose -f docker-compose.prod.yml exec nexguard ip rule show
# expected line: from all fwmark 0x1 lookup 100

# TPROXY chain (only present when l7_enabled = true)
docker compose -f docker-compose.prod.yml exec nexguard nft list chain inet nexguard l7_prerouting 2>&1 \
  | head -10
# expected (with l7_enabled = false): "Error: No such file or directory"
# expected (with l7_enabled = true): a chain with one TPROXY rule
```

## Operating the kill switch

To enable L7 enforcement (only after L7-D ships):

1. Confirm the L7 proxy daemon is listening on `127.0.0.1:8443`.
2. Flip the org toggle in the admin UI at `/settings/l7`. The
   `:l7_enabled_changed` PubSub event reaches `FzWall.Server`
   within a few ms; the TPROXY chain installs immediately.

To turn it off:

1. Flip the toggle off. The chain is removed within the same
   timeframe. Existing TCP connections in flight at the moment of
   the flip will continue (TPROXY rules only affect new packets
   that haven't been mark-set yet).

If something goes wrong, the safe rollback is **flipping the toggle
off** — no need to restart the container.

## Rollback (full)

To completely revert the L7-C deployment without redeploying:

```bash
docker compose -f docker-compose.prod.yml exec nexguard sh -c \
  "ip rule del fwmark 0x1 lookup 100 2>/dev/null; \
   ip route del local 0.0.0.0/0 dev lo table 100 2>/dev/null; \
   nft delete chain inet nexguard l7_prerouting 2>/dev/null; \
   echo done"
```

Then stop the container; on next start `fz_wall.Server.init/1`
will re-install whatever's appropriate for the current `l7_enabled`
value. If you need to permanently revert, redeploy v2.3.0.

## Operational notes

- **No L7 proxy daemon yet.** Until L7-D ships, flipping
  `l7_enabled = true` makes traffic to declared VIPs land in a
  closed port (TPROXY redirects to `127.0.0.1:8443` which has
  nothing bound). Real users of declared apps will see connection
  resets. Leave the toggle off.

- **CoreDNS hosts file mount path.** The default
  `${FZ_INSTALL_DIR:-.}/coredns-hosts` directory is auto-created on
  first `up`. You can change the path by setting `FZ_INSTALL_DIR`
  or by editing the overlay — keep the in-container path
  `/etc/nexguard` unchanged so Corefile's `hosts` directive still
  resolves.

- **IPv6.** Both halves of L7-C are IPv4-only in v2.4.0:
  - TPROXY rule matches `ip daddr 10.99.0.0/16`, not `ip6 daddr`.
  - CoreDNS hosts file only emits A records (we generate from
    `applications.virtual_ip` which is IPv4-only by ADR-014).
  L7-D will add IPv6 support to both.
